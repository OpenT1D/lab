## Fixed end-to-end boundary

The selected route has one implementation owner and a separate technical reviewer.
The fixed trusted launcher receives raw grants and independently reviewed source
context, derives the roots/profile/command and checks exact canonical setup and
execution memberships before private-path or channel intake. It rechecks current
source, live owner, root and byte bindings at the final spawn boundary.

Use the existing process owner and inherited FD3/4 exchange with a fixed exec
shim, preserving the observed child PID across exec. No request selects a command,
runtime, registry, policy text or native continuation. Raw grants never appear in
process arguments. A single bounded internal environment carrier supplies only
entry/observation bytes and source context. The large private packet is not an
environment payload. Refuse an oversized carrier or exec budget before spawn.
That preflight must cover allowed bootstrap metadata and each fixed exec stage,
not only the initially supplied carrier. A later shim bound is a second defense,
not evidence that the parent refused before acquiring a process.

The CLI owns and readmits the carrier and removes it before a version-2 exact
environment observation. Distinguish owner-supplied startup keys, runtime-added
keys and the actual post-removal environment. A fresh ordinary-tooling Mac
bootstrap exposes `__CF_USER_TEXT_ENCODING` in addition to the four supplied keys.
Do not remove that runtime key to make the historical three-key observer pass.
The new host context must independently bind the exact keyset and values; retain
those private values outside Git, and refuse unexpected keys or changes. A
Linux fixture without that key tests a different explicit policy and does not
establish Linux host qualification. The carrier, shim, runtime initialization and
complete startup path remain new host-qualification boundaries. Earlier tooling
and host receipts cannot attest them or the selected Node binary.

After exact declared admissions, acquire the eight fixed packet files once into
owned buffers. Validate all actual byte hashes and semantic memberships before
adopting protocol descriptors. Bind actual argv, owner start, attempt, nonce,
complete sources, profile and packet to the frame and exact acknowledgment.
Cancellation, EOF or changed source/owner/inputs cannot invoke a successful worker.

The fixed worker receives those same buffers and reuses the existing pure
engine/integration verifiers. It does not reopen packet paths after acknowledgment.
Only then may the admitted native branch register the fixed TypeScript loader,
load the four fixed upstream entrypoints and use the unchanged direct/wrapped

and separate primary/export errors remain observable.

The trusted route reader binds the actual outer receipt, frame/ACK, packet pins,
current route implementation and durable journal. A successful function call or

reader as well as consistent process completion. Interruption, external signals,
unfinished exchange and cleanup errors cannot be promoted to a completed result.
The single-attempt journal does not become a project-store seal or planned-slot

Bind the complete fixed outer argument structure, mode, nonce and declared origin
