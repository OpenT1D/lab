study before either first attempt and records a sealed materialization intent,

## Technical review and counterexamples

Separate read-only scientific/core and SDK/workbench reviews inspected the
actual implementation, callers and independent fixtures. Final production
review at clean `07c8c85f91dd760f9bc382729790dfa96ba24eb6` reported no remaining
actionable findings. A separate isolated writer supplied the core tests; the
root integration owner owns the final repository check. These are agent technical
reviews, not independent human reproduction or scientific validation.

Review and actual execution found and corrected:

- Canonical JSON key order could swap visits; every mapping now explicitly uses
  before/after order. Sampling owns schedule-specific required times rather
  than inheriting an inadmissible generated base setting.
- A premature final bridge could match absent child/comparison values through
  `None` equality. Non-null existing owner bindings are now required on write
  and replay. Interrupted intent/child/comparison boundaries remain recoverable.
- Caller Decimal precision, rounding and traps could change generated bytes.
  Generation and its independent integral use an explicit 50-digit context.
- Dense native sampling reports exceeded a generic 16-MiB metadata reader while
  remaining within the native report's declared 512-MiB budget. The adapter uses
  that existing native limit; other file/GUI/project limits remain unchanged.
- Programmatic study selection and temporary metadata loss could leave an old
  report beside a different study. Selection, late success/refusal, explicit
  forward choice and metadata recovery now preserve or withdraw matching report
  identities and downloads. The controlled select model now mirrors real empty
  select behavior, which the initial fixture had masked.
- The first actual native qualification completed all four forward slots, then
  refused bridge materialization. The bridge multiplied the equilibrium
  peripheral inventory in a different floating-point order. Native
  `k1 / k2 * central` gives `17.7687280176799`; the old bridge gave
  `17.768728017679898`. The fix uses the exact unchanged native expression,
  without weakening equality, scientific tolerances or frozen baselines.
  A nonbinary-basal regression passes; an in-memory old-expression control
  reproduces the intended refusal.

## Reader compatibility and limits

Before implementation, a real comparison project from merged `c0481d5` and its
exact JSON/Markdown/CSV report were copied and successfully reconstructed with
its original wheel. The new 138-file comparison reader closure differs from
the original 134-file closure. The preserved project refuses with
`Frozen comparison/source identity differs`; its original bytes and reports
remain unchanged. This is explicit unsupported-reader refusal, not a supported
upgrade. Roadmap step 6 owns the distinct application/reader transition.

The selected runtime is local macOS arm64 with POSIX CPython 3.12 and separately
reviewed, locked native/observer roles. Root/public checks use the standard
library and controlled fixtures; they supply no hosted native numerical result.
No new task, dependency, model, kinetic calibration, sampling-selection rule,
estimator, biological result or distribution permission is introduced. Two
source-method cases are not people or an independent cohort. The stimulus
contrast, positive engineering perturbations and descriptive reduced schedules
do not establish treatment effects, assay precision or empirical equivalence.
Independent usability, human-data evaluation, clean-host/application packaging
and broader platform qualification remain separate gates.
