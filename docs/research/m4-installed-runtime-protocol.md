# Installed M4 execution protocol

`M4-STUDY-INSTALLED/1` identifies an internal execution successor to the frozen
maintained M4 study. It reuses the original scientific functions and their
protocols, solvers, tolerances, units, native source/parameter identities,
240-minute horizon, quarter-minute grid, basal replacement and C-peptide
ownership. The original maintained and historical execution identities retain
their original locks, source inventories and readers.

The new native project retains NumPy 1.26.4, SciPy 1.13.1, pandas 2.2.3,
Matplotlib 3.9.4 and both exact upstream commits. Its 34-distribution closure
changes only certifi to 2026.10.23, Pillow to 13.0.0 and setuptools to 84.2.1.
The separate twelve-distribution observer retains NumPy 2.2.6 and SciPy 1.15.3
and changes only Pillow to 13.0.0. Build inputs have a separate lock, including
wheel 0.46.2 and the complete pinned hatchling closure. Runtime review is dated
and scoped; a package inventory is not a guarantee against future advisories.

Execution uses the current trusted CPython 3.12 coordinator executable for
every fresh process with `-I -B -S`. A caller explicitly attaches two distinct
verified dependency directories. The attachment records full file/package/git
inventories, selectors, interpreter identity and current source payload. Each
fresh process verifies this current binding, sets a private bytecode-cache
prefix and adds only its selected role's site-packages; it does not process
`.pth`, sitecustomize or PYTHONPATH. No interpreter, command, module or dependency
path is selected from an archive. This is explicit local code trust, not an
operating-system sandbox or cryptographic authentication of a hostile owner.

Pinned gym still imports `distutils.version`, removed from the Python 3.12
standard library. The native startup context explicitly invokes the reviewed
setuptools 84.2.1 distutils finder, alongside the existing two resource/
entry-point compatibility APIs. It never evaluates `.pth` text or edits an
installed upstream file; the dedicated process restores the import contexts.

New plan, reference, report and attestation schemas identify this dependency-
overlay execution. Inherited scientific JSON formats retain their scientific
meaning. Actual commands, dependency receipts, attachment and live ownership
evidence are separate from numerical trajectories. Each complete result must
pass all reference/source/observer gates and exact fresh-process repeats.
Run cancellation is queued before metadata and publication; cleanup retains
live process start identities with nested numerical/reference/service/caller
graces of 10/20/30/40 seconds. Unknown cleanup cannot be sealed as success.

The matching trusted reader validates complete archived evidence, original
inputs, source declarations, protocol/lock/helper identities, actual runtime
receipts, ownership and command ledger, numerical criteria and descriptive
contrasts. It requires no attachment or simulator installation and never loads
an archived callback. Complete JSON/Markdown/SVG reports must reproduce exactly.
Failed evidence requires explicit opt-in and retains unavailable denominators.

Direct-versus-installed parity uses the same newly admitted dependencies and
fixed synthetic inputs. Numerical artifacts must match exactly, apart from the
original explicitly permitted patient/parameter installation locations; paths,
timings, command logs, attestations and seals are recorded execution metadata.
This does not reproduce an excluded historical environment. Broader historical
parity, public distribution/table rights, independent usability and biological
validity retain separate gates. Evolving results belong in the separate
[verification record](ot060-native-m4.md), outside this frozen source guidance.
