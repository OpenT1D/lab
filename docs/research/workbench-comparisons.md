## Acceptance and counterexamples

1. Freeze complete labelled variant/plan rosters before any member plan runs.
   Show changed assumptions/selectors; refuse prior execution, duplicate members,
   incompatible task/endpoint/support/units and altered development evidence.
2. Run unique plans sequentially through the existing SDK lease and cancellation
   boundary. Several members may reuse one plan's first native attempt. Retain
   failed, incomplete, unattempted and unfinished cases with complete denominators.
3. Reconstruct a comparison from authoritative native readers without rerunning
   supplied models. Bind exact plans, attempts, native hashes, adapter identity
   and ledger prefix. An old prefix reproduces exact report bytes after later
   execution, retries, restart and relocation; originals remain unchanged.
4. Independently check descriptive differences and signs using calculable saved
   endpoints/trajectories. Keep point and interval completeness separate. Refuse
   tampered/resealed evidence, changed units, shortened supports, missing rows and
   successful prefixes from otherwise failed native M4 sources.
5. Expose the same frozen comparison and downloads through installed Python/CLI
   and the workbench. Exercise real noneditable installation and browser flows,
   correction, keyboard/focus, stale results, cancellation and reconstruction.
6. Run `uv sync --locked` and one final `uv run --locked python scripts/check.py`
   on the integrated revision, plus relevant installed/browser checks. Record
   actual outcomes, source identity, skips and unresolved limits separately from
   hosted CI. Do not change frozen numerical criteria to obtain a pass.
