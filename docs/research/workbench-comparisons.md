## Acceptance and counterexamples

1. Freeze complete labelled variant/plan rosters before any member plan runs.
   Show changed assumptions/selectors; refuse prior execution, duplicate members,
   incompatible task/endpoint/support/units and altered development evidence.
2. Run unique plans sequentially through the existing SDK lease and cancellation
   boundary. Several members may reuse one plan's first native attempt. Retain
   failed, incomplete, unattempted and unfinished cases with complete denominators.
3. Reconstruct a comparison from authoritative native readers without rerunning
   supplied models. Bind exact plans, attempts, native hashes, adapter identity
   and ledger prefix. An old prefix reproduces exact report bytes after later
   execution, retries, restart and relocation; originals remain unchanged.
4. Independently check descriptive differences and signs using calculable saved
   endpoints/trajectories. Keep point and interval completeness separate. Refuse
   tampered/resealed evidence, changed units, shortened supports, missing rows and
   successful prefixes from otherwise failed native M4 sources.
5. Expose the same frozen comparison and downloads through installed Python/CLI
   and the workbench. Exercise real noneditable installation and browser flows,
   correction, keyboard/focus, stale results, cancellation and reconstruction.
6. Run `uv sync --locked` and one final `uv run --locked python scripts/check.py`
   on the integrated revision, plus relevant installed/browser checks. Record
   actual outcomes, source identity, skips and unresolved limits separately from
   hosted CI. Do not change frozen numerical criteria to obtain a pass.

## Implemented boundary and development checks

The installed Python/CLI and thin workbench use an immutable `comparison` project
event. Historical plan/attempt schemas and numerical code remain unchanged.
Each roster has 2–16 exact plan/selector members and one named baseline. Intake
requires unused plans and compatible native readers, protocol/source/runtime,
original observations/allocation/visit order and sampling development evidence.
Concrete selected assumptions, times and initial load/source identities accompany
the changed-field view. Existing sequential runs own execution and cancellation.

Report reconstruction takes a read-only project lease and invokes the existing
authoritative native readers. Exact native hashes, first attempts, complete
planned cases and ledger prefix are retained. The comparison reader binds its
complete static local dependency inventory. Sealed JSON/Markdown/CSV contains
task-owned descriptive quantities and explicit units, without a common biological
score, new uncertainty interval, allocation pooling or replacement of failures.
Old ledger tips keep unfinished/unattempted status even when evidence arrives
later. Full project copies retain those tips; convenience report copies remain
workspace state. Snapshot tips and selected native report hashes are in each JSON.

The development owner uses root CPython 3.12, Node 24 and real noneditable SDK
environments. The targeted commands are:

```bash
uv run --locked python -m unittest \
  tests.test_plan_comparisons tests.test_installed_comparisons \
  tests.test_installed_gui tests.test_installed_gui_frontend -v
npm --prefix tests/browser test
```

Core cases use analytical constant-concentration controls: a 0–120-minute total
is `volume_l * k3_per_min * concentration_pmol_l * 120`; a 20-percent volume
contrast changes that total by exactly 20 percent within the unchanged native
tolerance. Constant M4 trajectory contrasts independently check signed integral,
time mean and maximum absolute differences on all 961 samples. Other cases retain
forensic failure/unattempted denominators, later successful retries, prefixes
ending before a later finish, expired leases and changed helper identities.
Point availability remains distinct from required-draw/interval completeness.

Actual installed cases exercise Python/CLI/HTTP parity, two task families,
development/evaluation separation, three-file downloads, old-prefix replay after
restart/project copying and supported M4 configuration/admission failures. The
real Chromium comparison flow includes within-plan and derived-plan members,
shared first attempts, unattempted/current reports, exact old snapshot downloads,
restart, keyboard focus and narrow/200-percent text. Earlier browser flows retain
their separate lifecycle, sampling, cancellation and correction coverage.

Separate read-only core and GUI reviews reproduced six issues: incomplete helper
source binding, selector-only rather than resolved scientific changes, expired
service reads, late report replacement, stale selection status, and cancellation
of a new report load while withdrawing an invalid old copy. Corrections
bind the full source closure, show numeric changes and enforce leases, verification
epochs, separate display withdrawal and current comparison context. The controlled frontend wrapper has 30
cases; three new report/status cases fail on saved pre-fix JavaScript and pass
after correction. A fourth regression fails on the intermediate report guard
when an old refusal/invalid poll cancels a newer load, and passes after correction.
Other cases preserve roster metadata/explicit baseline after
project switching or refusal and reject late selector responses. Agent review is
technical evidence, not independent scientific or intended-user acceptance.

Development initially used a noncanonical temporary path; existing file guards
refused it, and canonicalising the owned temporary fixed the reader invocation.
An early browser text-size probe attempted an inline stylesheet and was correctly
blocked by CSP; it now uses the existing direct DOM text-size mechanism. Neither
failed run supplies acceptance. Native protocols, scientific files, references,
tolerances and OT-059 fixtures are unchanged.

## Final receipts and remaining gates

The integration owner runs `uv sync --locked` and one final full
`uv run --locked python scripts/check.py`, the complete Chromium family and a
clean retained installed SDK rehearsal on the final integrated revision. Exact
source/dirty state, toolchain, wheel identity, actual outcomes/skips, failed
development logs and technical review are retained under ignored
`results/workbench-comparisons/` and stated in the PR handoff. Local commands are
distinct from hosted CI; an earlier tree does not qualify a changed final tree.

The separately selected native M4 rehearsal prepares only the reviewed
native/observer/build locks, attaches them explicitly to the current SDK and
freezes a complete fasting/15-g source/load comparison before execution. Its
receipt must show all original native reference/observer/repeat/grid gates and
comparison reconstruction/relocation without dependency or callback lookup.
Installation, controlled arithmetic fixtures and passive refusal do not substitute
for that success receipt. Keep upstream parameter/runtime payloads local.

Current-artifact native M4 execution requires its reviewed attachment and separate
qualification. Passive intake, controlled report fixtures or refusal do not supply
that evidence. Independent users, screen-reader/accessibility qualification,
other-host/release checks and the later changed-reader transition remain open.
