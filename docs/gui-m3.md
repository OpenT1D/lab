# Run synthetic M3 forecasts in the local interface

This implemented OT-042 increment exposes the existing
[M3 forecast](m3-researcher-forecast.md) and
[frozen-candidate comparison](m3-candidate-comparison.md) in the
[local interface](local-gui.md). The [verification record](research/m3-gui-verification.md)
binds local internal acceptance; independent researcher use remains open.

## Prepare and check

Start the local GUI from its identified locked checkout. For independently
retained output, provide an existing canonical external `--archive-store`.
Create the original synthetic example explicitly, or select a permitted relative
configuration from an allowed root. Inspect metadata, select one frozen predictor
for a forecast or at least two for a comparison, then prepare a new configuration.
Preparation explicitly copies synthetic observation bytes and records that access;
it does not fit a predictor. Original configuration, declaration, source and
settings bytes are preserved. Effective configuration changes record the selected task, predictor roster,
per-participant worker budget and relocated paths. A metadata readiness check does not inspect observation
contents, establish prediction performance or execute selected predictor code.

## Execute and inspect

A matching readiness check enables explicit execution. One operation may run
across the whole workspace. Progress reports observed state; cancellation asks
owned processes to clean up and preserves available evidence. Native JSON and
Markdown retain every planned person/origin and failed or unattempted case.
Comparison uses the native common support. Execution success, authoritative
reconstruction and complete cohort are shown separately. Downloads contain
native bytes; the browser does not recalculate metrics.

Explicit reconstruction invokes the saved-analysis reader without rerunning a
predictor or reopening original preparation inputs. An unsealed cancelled forecast may have no report. Preserve those
raw files with the separate retention action. This creates a fresh independently
stored inventory and provenance receipt, not a verified durable package.
A sealed partial comparison can retain an unsealed child and remain readable.

## Preserve evidence

Sealed forecast/comparison archives use the
[durable archive workflow](durable-experiment-archives.md). Export invokes the
fixed M3 reader and refuses changed saved reports. Restore preserves original
files and child archives byte for byte. Explicit reconstruction requires a
compatible clean trusted checkout at the recorded full Git revision; preserved
reader files remain data and are never selected as executable code.
Integrity verification alone does not prove authoritative reconstruction or
complete prediction coverage. Retention grants no resume or process authority.

This synthetic workflow does not process a human release, establish empirical
forecast accuracy or replace independent researcher usability assessment.
