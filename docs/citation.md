# Citation and research credit

Use [CITATION.cff](../CITATION.cff) for the project's machine-readable citation metadata. It is validated by the repository checks.

## Current repository

OpenT1D has no software release, DOI or associated project paper yet. Do not cite a planned release or invent a publication. When referring to development material, cite the repository and include the exact commit identifier and access date in your work.

The current named author is the founding contributor. Update the metadata as substantive contributions are incorporated, with the contributors' agreement about their names and attribution. Do not list institutions, affiliations or ORCIDs that have not been supplied and verified.

## Experiments

Cite the OpenT1D version used and the underlying model papers, software versions, parameter sources, datasets and important analysis methods. The experiment manifest should identify these inputs so that a report can eventually produce the appropriate reference list.

An OpenT1D citation does not replace credit to upstream researchers. Software contributions, scientific review, data preparation and reproduction work should all be acknowledged accurately. A repository contribution does not automatically imply authorship of every later paper.

## First archived release

Before archiving a release, review author metadata, version, release date and artifact contents. An archive such as Zenodo can assign a DOI; add it to the citation metadata only when the record exists. Test the archive workflow before making it the project's official citation target.

Preserve the connection between a scientific result and its exact software, protocol, model and data versions. The [maintenance guide](maintenance.md#releases) describes release and correction responsibilities.
