# 0111 — Matched LT1 host probes and original-tree removal

## Context

The version-2 native route joins fixed launch, owned channels and packet buffers,
durable scientific sessions and strict readback. Its selected-runtime setup and
native host qualification remain unrun. A denied operation without a successful
matched control can reflect an unavailable target. The existing flat remover
cannot remove original session subdirectories and their separate execution
records. Removing a flattened copy would leave those original objects behind.

## Decision

Deliver the matched host probe and original-tree removal in one successor PR.
Reuse the current native route, process owner, storage primitives and recovery
assessors. Keep historical readers/source inventories and scientific contracts
unchanged. All four canonical operational authority lists remain empty.

C19 is a fixed base/allow-twin pair. Validate both grants, owned packets and
physical contexts before any canary, listener or process. Use one immutable stage
and one shared physical evidence root, distinct packet/output roots and fresh
per-slot nonces. The root-owned `native_attempt_namespace.json` fixes role and
leaf names for both components. Seed six fixed canaries only after admission;
revalidate their identities/bytes and the preserved base artifacts before the
twin. No public preexisting-inventory, command, runtime, target or policy selector
is introduced. Existing cases keep their fresh-empty-root requirement.

The twin adds only two literal evidence-canary accesses and one fixed loopback
endpoint. Both slots exercise the same physical targets and parent-owned
listener. Bind observed reads, writes and accepted challenge bytes independently
in the parent; nonces do not establish a kernel TCP peer PID. An unavailable,
busy, timed-out, changed or unclearly cleaned-up control is inconclusive. Require
actual successful matched controls before calling a base permission error a
demonstrated denial. Separate scientific completion, operation reports and the
paired assessment. Broader bootstrap, addon/module, IPC and resource acceptance
remain open; no C19 result grants full native qualification.

Add a separate fixed-depth remover for one allocated output or evidence tree.
A C19 pair has three targets: two outputs and one shared evidence root. Accept
partial/failed/empty known trees without model replay; refuse unknown names,
links, special files and changed bindings. Preserve the existing flat remover.
Exact canonical removal-list membership precedes private path/process intake.
Bind request identity to the code/Python projection excluding only the three
mutable authority files; audit the complete current source after publication.
Historical producer pins are data, not a requirement to restore old permissions.

Exclusively quarantine the whole reviewed root on the same volume, journal and
sync each phase, remove known leaves/directories and close owned content FDs
before completion. Recheck descriptor/name bindings and expected namespaces;
account for legitimate directory timestamp changes caused by the remover itself.
The new reader binds original and quarantine parents, including the final absence
of both roots. Preserve real outer receipts, cancellation/deadline/failure
prefixes and unrelated siblings; missing outer evidence remains missing.

Complete readback may propose absence only for that allocated root copy. Keep
input registers, origin clocks, holds, other copy IDs and recovery blockers
unchanged on incomplete outcomes. Requests, journals, logs and readbacks create
additional private records requiring accounting. Other stage/packet/relocated,
backup/snapshot and unregistered copies remain outside this removal. Namespace
absence establishes neither original absence timing, retention compliance,
ordinary restore exclusion nor physical sanitization. Effective erasure remains
unverified.

## Acceptance and remaining gates

Use freshly generated invented trees under the real owned worker. Exercise full
original output/evidence removal, partial and malformed data, each interruption
phase, links/unknown names, namespace/journal/source changes, missing outer
receipts and unrelated controls. Check exact allocated-copy proposals without
changing original timing, holds or other copies. Challenge C19 with missing
positive controls, unavailable/busy endpoints, unexpected base allows, wrong
nonce/seed/profile/context and incomplete reports; retain both planned slots.

Two isolated implementation owners cross-review the final components; root owns
the shared namespace and sole final full repository check. Any actual ordinary
Mac tooling-profile experiment requires reviewed exact fixture source, fresh
invented targets and bounded local I/O. It does not import the selected native
runtime or qualify it. Actual selected-runtime setup/execution, private deletion,
complete copy/restore coverage, rights acceptance and effective erasure retain
separate gates. Software checks establish no biological validity.
