Use a short decision record for choices that affect shared architecture, scientific conventions, substantial dependencies, licensing or project direction. Routine implementation details can stay in their issue or pull request.

Number records sequentially and give them a descriptive filename. Each record should contain the status, date, context, decision, alternatives, consequences and conditions for revisiting it. Link the relevant discussion and evidence when available.

Statuses are **proposed**, **accepted** or **superseded**. An accepted record describes project policy; it does not imply that the planned system is already implemented. Preserve a superseded record and link to its replacement.
