# 0096 — Durable LT1 attempt integration without admission transfer

Date: 2 November 2026. Status: accepted for implementation; native execution unadmitted.

## Context

The [worker successor](../research/ot062-lt1-native-worker.md) exports only after
simulation. Process termination can therefore lose its valid callback prefix.
The [host fixture record](../research/ot062-lt1-host-qualification.md) demonstrates
scripted process behavior but supplies no native launch or project-store route.
Signature authentication alone also cannot supply runtime/security or use rights.

## Decision

Add a separate integration entry with a versioned append-only attempt journal and
engine-free reader. Keep the original workers, trace reader, locks and scientific
protocol unchanged. Require both the existing exact engine grant and a separate
exact integration envelope in the fixed reviewed execution registry. The existing
setup-receipt requirement still applies. No production entry is added to either
admission list.

The envelope additionally binds the attempt, private output root, live owner PID,
integration host receipt, current integration JavaScript and frozen reader
identity. Read and compare every declared reader source byte before journal
creation or TypeScript registration. The complete Python import roster must be
generated by the trusted Python identity function and reviewed with the envelope;
the Node worker does not compute a Python AST closure. The data reader independently
recomputes the full current identity and refuses stale/incomplete declarations.

Create the header before native import/initialization. Fsync each row only after
the existing callback validator succeeds. Preserve native reset, solver, sensor,
controller and pump ownership. A callback owner check may stop a lost-supervisor
attempt; it is not immediate solver interruption or descendant confinement.
Retain primary errors and journal-export errors separately. Missing/torn tails
never become completed intervals. A worker footer cannot promote a failed or
interrupted process receipt; observed external signals remain noncompleted.

## Consequences

This is a single-attempt boundary, not another process manager or ledger. Tests
use fixed invented constructors and the existing supervisor. The native entry's
positive TypeScript/engine branch remains unrun. The project store still needs a
reviewed route that freezes complete source identities, records every planned
slot/attempt/retry and supplies trusted artifact/receipt hashes. Relocated data
can be read with current trusted code without importing archived code.

The [follow-up record](../research/ot062-lt1-auth-integration.md) separates the
authenticated archive signature, pending rights dossier, tested fixture behavior
and remaining setup/host/native gates. No checksum, dossier field, supplied JSON
or fixture success can register an admission or qualify native C15–C18.
