# 0112 — LT1 loader controls and immutable packet removal

## Context

The matched C19 probe checks bounded file and loopback behavior, not module or
addon loading. Original output/evidence removal leaves the separate immutable
eight-member native packet roots. Selected-runtime setup, rights/runtime
acceptance, native host qualification and effective private erasure remain open.

## Decision

Deliver ordinary-tooling loader controls and original packet removal in one
successor PR. Reuse the unchanged process owner, source identities, tree worker,
strict readback and allocated-copy reconciliation. Preserve scientific contracts,
historical 156/49/170 source inventories and all four empty operational lists.
Describe the approach in this draft before implementation; do not merge a
separate preparation layer.

Use one source-owned JavaScript module and a minimal N-API addon with fixed marker
exports. Compilation and actual Mac profiles are explicit reviewed experiments,
outside automatic root checks. Use only the fixed preinstalled tooling compiler,
SDK, headers and ordinary Node; never install a toolchain or invoke the selected
native candidate. Bind source, compiler/linker/header closure, runtime and emitted
artifact identities and preserve partial preparation records.

Account for three fixed slots: unprofiled validity control, base and allow-twin.
Use the same immutable physical artifacts and a fresh process for each slot.
The validity control must load both targets successfully. Base permits addon
data reads, withholds module-data read and explicitly denies the addon's literal
executable mapping. Twin omits only that deny and adds the two corresponding
literal permissions. Absence of an explicit mapping allow did not block the
readable addon in the first successful-build Mac experiment. A separately
reviewed diagnostic blocked it with the explicit deny while preserving positive
controls; retain that negative predecessor rather than relabeling it a pass.
Keep reads, actual imports,
returned markers, owned outer receipts and parent artifact snapshots distinct.
An addon loader error alone is not a permission diagnosis. Missing, malformed,
changed, interrupted or failed positive controls remain inconclusive; unexpected
base success cannot demonstrate confinement. No result qualifies native LT1.

Add the fixed `native-packet` namespace role: exactly the original eight names,
no subdirectories, root mode `0500` and single-link leaf mode `0400`. No import of
the native route or model is needed to delete these bytes. Exact canonical
removal membership still precedes caller, source, private path and process intake.
Preserve the existing output/evidence behavior and old flat remover.

Quarantine the whole reviewed original root exclusively on the same volume.
For this immutable packet role, use the source-derived sibling name
`lt1-packet-<sha256(request_raw)>` under the original private parent; the separate
cleanup attempt holds its journal. The Mac fixture refuses cross-parent moves
of a `0500` directory, while a same-parent exclusive rename succeeds. Do not
change the original mode to make a cross-parent rename work. Existing writable
output/evidence trees retain their cleanup-attempt quarantine location.
Only then may the held root descriptor undergo the fixed `0500` to `0700`
transition. Sync it and record a distinct `packet-writable` event before unlinking
leaves. There is no caller-selected mode or path chmod. The writer and reader
must bind the actual mode at each phase; a crash after chmod but before its event
is an explicit incomplete mutation gap, never a manufactured event. Preserve
real cancellation/deadline/outer evidence and final absence of both root names,
including a sibling quarantine when the journal attempt is missing.

Only complete strict readback may propose absence for that allocated packet-root
copy. Preserve original clocks, holds, other copies, producer history and all
new record-accounting blockers. Other packet copies, staging, memory, compiled
tooling artifacts, snapshots and backups remain outside this removal. No register
activation, original absence timing, restore exclusion or physical sanitization
claim follows.

## Verification and gates

the shared namespace and final full repository check. Root CI tests portable
contracts and fresh ordinary fixtures without invoking a compiler or Mac policy.
Actual loader experiments require reviewed exact sources and pinned installed
tools. Test valid and unavailable targets, changed bindings, missing positive
controls, mode/event contradictions and actual owned packet removal/crash gaps.
Keep selected-runtime setup/execution and effective-erasure authority false.
