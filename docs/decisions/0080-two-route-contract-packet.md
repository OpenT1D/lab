# 0080 — Freeze a two-route metadata contract before extraction

Date: 29 October 2026

Status: accepted for the internal OT-059 packet; families remain provisional.

## Context

[Decision 0070](0070-common-research-laboratory.md) selects shared project,
execution and result services. Existing native tasks and offline MMTT analysis
have different scientific contracts and reader identity policies. A universal
step callback would erase meaningful differences before a second engine tests
the proposed boundary.

## Decision

Freeze version 1 of a small internal project/asset/plan/attempt/result metadata
packet around `m4-study-secure` and `mmtt-sensitivity`. Bind exact scientific
input bytes and task-owned protocol, source and runtime-file identities. Derive
planned source/scenario or participant/variant slots through passive native
validation. Keep the full scientific configuration, uncertainty and atomic
attempt ledger in the original task payloads; a shared slot is an administrative
projection, not a replacement denominator.

Use content identities, project-relative asset paths and explicit parent-plan
links. A changed plan creates a new identity. Separate process completion,
scientific completeness, recorded reconstruction and scientific evidence.
Metadata validation does not verify native result arithmetic or authenticate a
recorded reconstruction claim; use the authoritative trusted reader explicitly.

Inventory all ten registered routes, including their differing historical
reader rules. Keep sampled stateful control, continuous pure RHS sources,
forecasting, frozen prognosis and retrospective analysis as provisional
capability families. Preserve units, compartments, availability, actual versus
announced events and process ownership in native contracts. Do not load code
named by metadata or archived snapshots. A second native-engine integration
must exercise the shared families before they can become compatibility claims.

## Consequences

The [contract guide](../shared-core-contracts.md) and executable fixtures are the
handoff to minimal OT-061/064, then OT-060. This packet does not migrate routes,
implement storage/runtime services, publish an SDK, install historical runtimes
or qualify a platform. Full native M4 success, parity, reader upgrades, process
ownership on each host and independent usability retain separate gates. The
current M4 activation context is not thread-safe; future concurrent execution
must retain isolated workers rather than share its mutable module bindings.
