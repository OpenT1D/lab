# 0109 — LT1 entry continuation and packet-copy reconciliation

## Decision

Add two versioned consumers after the candidate host-plan and packet-cleanup
increment. Keep existing launchers, workers, profiles, readers, source inventories
and all four production authority lists unchanged.

Select a prepare-only Python interface and a native-entry continuation library.
The canonical exact setup/execution memberships must precede private-path or
descriptor intake. Bind the new entry/source closure, fixed process arguments,
profile, owner and nonce separately from the existing observation producer.
Complete the inherited FD3/4 frame/ACK exchange before the fixed integration
worker continuation. Accept no caller-selected command, runtime or native
delegate. Raw grants travel through a trusted-code API, not self-referential
process arguments. No new native launcher or CLI is selected. Ordinary tooling
Node and a fixed invented continuation exercise the channel boundary only.

Select a separate packet-copy reconciliation reader. Externally pinned retained
packet/intent/accounting/provenance, request/context, journal and actual owned
process receipt bind the exact deleted packet without reopening it or replaying
original live evidence. Use the unchanged strict removal reader. Only complete
whole-packet readback may propose absence for explicitly allocated packet-copy
IDs; incomplete outcomes retain the supplied accounting bytes exactly.
Preserve all other copies, original clocks/holds, history and recovery coverage.
Keep historical packet and actual removal contexts distinct. Recheck source and
live readback before returning an unsaved, unapproved proposal.

## Consequences

Old host receipts do not qualify the new entry/profile. Native bootstrap, module,
addon, process, file/network and host-mechanism cases and C15–C18 remain unrun.
Actual setup and bounded native execution still need their separate reviewed
admissions. A packet-copy absence proposal proves neither absence onset, timely
private retention compliance, complete restore exclusion nor physical erasure.
Saving returned metadata creates further private copies requiring accounting.
No existing private pilot, backup, snapshot, container or key is accessed or
removed by this increment. Agent and fixture checks establish no independent
human or scientific qualification.
