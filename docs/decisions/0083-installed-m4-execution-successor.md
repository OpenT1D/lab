# 0083 — Identify installed M4 execution separately from historical runtimes

Date: 29 October 2026

Status: accepted for implementation; numerical and relocation acceptance pending.

## Context

The historical `m4-study-secure` protocol binds every dependency and runtime
selector exactly. Its native and observer environments are excluded by the
public installation policy. Replacing dependencies while retaining that
execution identity would misrepresent its evidence. The installed SDK currently
retains passive inputs and failed readers, without native execution.

## Decision

Add an explicit internal `m4-study-installed` execution successor with new
schemas, protocol, native/observer locks and a trusted SDK/service registration.
Preserve the original ten-route registry, frozen inventories, historical source
files, locks, protocols and readers. Reuse unchanged scientific functions and
their original criteria, source declarations, model/parameter ancestry, units,
basal ownership, solvers and time grid. New execution metadata never becomes an
old scientific execution record.

Review complete runtime and build closures before installation. Keep the
existing numerical pins and upstream commits; patch the independently identified
ancillary dependencies. Rights review covers the actual local use and notices;
this does not authorize bundling upstream parameter tables or public release.

An explicit installation-scoped runtime attachment identifies two environment
roles, selectors, interpreters, site-packages and complete admitted file/package
inventories. It remains outside the immutable source/data wheel and project.
Each fresh coordinator/worker uses fixed trusted bootstrap code and verifies
the current attachment. Archived paths and descriptors are inert provenance,
never executable authority. Workers use isolated Python startup, explicit
verified source/site paths and independent bytecode-cache handling. No desktop
manifest, legacy ROOT redirection or implicit environment discovery is used.

Queue run cancellation through metadata, ledger publication and terminal sealing.
Own every fresh process tree with live start identities, bounded nested cleanup
and unrelated-process preservation. Unknown cleanup cannot become success.
Reconstruction uses only the matching trusted standard-library reader, without
attaching, probing or launching a numerical environment.

## Acceptance and limits

Run the preserved numerical checks and selected fasting/derived 15 g plans,
each with both original sources and all primary/repeat/reference/observer gates.
Compare direct trusted-source execution and installed execution under the same
new environments with predeclared scientific artifact equality. This tests
migration parity, not reproduction of an excluded historical environment.
After removing original input/checkout/environment locations, reopen the whole
project and reproduce complete JSON, Markdown and SVG bytes with no simulator.
Keep failed attempts and test altered runtime/source/grid/ledger evidence.

Broader historical parity, OS qualification, public distribution, independent
user reproduction and biological validity retain separate evidence requirements.
