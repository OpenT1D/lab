# 0091 — Reuse project services for frozen synthetic M3 comparisons

Date: 1 November 2026. Status: selected before implementation.

## Decision

Migrate the existing `m3-compare` coordinator and its unchanged `m3-forecast`
children through the SDK project ledger and editable workbench. The parent is
the comparison: do not reinterpret its candidates as generic cross-plan
comparisons. Keep the legacy CLI, archive schema, numerical implementation,
protocols and authoritative readers unchanged. The integration owner owns all
shared interfaces and the final locked repository check; a separate reviewer
will challenge the final diff and counterexamples.

Add an explicit descriptor-6 developer wheel with the existing ordered four
routes followed by `m3-compare`. Preserve descriptor 1–5 rosters and both
candidate build switches. This source/data wheel ships no native dependencies.
The bounded predictors run in the installed POSIX CPython 3.12 standard-library
worker; fitting a genuine Ridge donor remains in the separately locked,
policy-allowed M3 estimator environment. No arbitrary dependency installation,
training pipeline, human-data intake or stable plugin API is selected.

Installed provenance is supplied by a fixed trusted SDK context, using the
verified application descriptor's source revision/dirty state. The historical
M3 modules otherwise ask Git for that administrative identity. Bind their
imported identity function in each fresh installed coordinator/child process;
reroute only the fixed comparison-to-researcher child command through the
verified bootstrap. Keep all historical source/protocol/lock bytes and reader
hashes unchanged. This selects no environment-provided or archived executable
entrypoint and does not fabricate a Git checkout or desktop runtime manifest.

Freeze exact original configuration/declaration/source/settings bytes and a
bounded snapshot of every readable planned observation before execution.
Unavailable observations retain a typed capture failure and an absent effective
input; changed hashes and malformed observations remain worker failures, never
silently repaired. Freeze all participants, origins, candidate order, prior
access and worker budgets. A per-attempt invocation rebases only explicit file
locations to these frozen snapshots; the native archive records that invocation.
Reading binds it back to the shared freeze, including exact supplied bytes.
Archived source is data: only explicitly requested execution loads a predictor.
Relocated reconstruction uses current trusted readers without original inputs.

Preserve six exact five-minute CGM values, causal availability, integer elapsed
microseconds, 30-minute horizon and mg/dL. Preserve persistence, all-candidate
common support, complete-worker eligibility, 288 origins and 24-hour span,
equal-person weights, bootstrap, all exclusions and partial prefixes. Completion
and cohort completeness are separate. Shared slots are candidate/person pairs;
native reports retain every planned origin and persistence/support details.

Workbench concepts edit the comparison JSON and reference explicitly chosen
local synthetic observation and reviewed predictor files. Validation captures
their identities without executing callbacks; freezing repeats that capture
and refuses changes since validation. Export for derivation rebases retained
resources into fresh editable copies; it never executes archived source.

## Preselected acceptance

1. Actual noneditable wheel outside a checkout: Python/CLI/workbench plan IDs,
   complete native reports and direct/installed prediction/metric parity.
2. Refuse altered declarations, source/settings hashes, extra future features,
   unknown readers and resealed changes. No predictor import during intake or
   reconstruction. Review an explicit GluPredKit mapping after this boundary.
3. Preserve missing, invalid and late/unavailable CGM, failing/nonfinite/slow
   predictors, unattempted candidates and all original denominators. A long
   failed prefix cannot contribute. Preserve unfinished starts and explicit
   retries using the existing ledger/process ownership.
4. Cancellation/deadline retain evidence and clean owned descendants while an
   unrelated process survives. Reopen and relocate complete/incomplete reports
   with original inputs and predictors absent; require exact report bytes.
5. Actual installed browser concept/validation/freeze/run/read/download/reopen
   flow, correction and narrow/200-percent reflow. Targeted counterexamples,
   separate critical review, final `uv sync --locked` and full repository check.
   Verify the latest remote attempt at its exact source/merge revision.

Existing M4 artifact qualification does not qualify this new wheel. Record local,
installed, estimator, browser and hosted evidence separately. Independent use,
human predictive accuracy, biological validity and distribution remain open.
