# Support

The initial public source exercise is limited to the two synthetic MMTT tasks.
Historical native environments have [installation restrictions and open
advisories](docs/publication-security.md); their guides preserve research routes
rather than promising a currently maintained public runtime.

OpenT1D provides checkout-based research workflows and a local browser interface. Support covers documented setup, synthetic examples, saved-report reconstruction, defects and scientific corrections within those declared contracts. There is no supported versioned release, stable general model API or guaranteed support service.

| Need | Where to go |
| --- | --- |
| Understand the project | [Documentation](docs/index.md) and [roadmap](ROADMAP.md) |
| Ask a project question | [GitHub issues](https://github.com/OpenT1D/lab/issues), using the question category |
| Report a defect or scientific error | The relevant [issue form](https://github.com/OpenT1D/lab/issues/new/choose), with a minimal reproduction or source |
| Propose a model, protocol or feature | The proposal issue form and [contributing guide](CONTRIBUTING.md) |
| Report a vulnerability | [Security policy](SECURITY.md) |
| Report unacceptable behavior | [Code of conduct](CODE_OF_CONDUCT.md) |

The public source destination is `OpenT1D/lab`; historical development links may refer to a separate private archive. There is no separate support service or response-time guarantee. Please keep one topic per issue and include the commit, environment and commands when reporting a technical problem.

The project cannot provide individual medical advice, dosing recommendations or device troubleshooting for clinical use. Do not attach personal health records to a support request.
